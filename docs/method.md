# 实现与公式

## 节点中的三层循环

Bpbc.solveNode() 与 Algorithm 1 对应：先用船舶 CG 求 BMP，固定船舶流量形成任务时刻需求，再用引航员 CG 求 PBSP；若引航成本大于 η，就加割并重新求 BMP。

Master.columnGeneration() 与 PilotProblem.generate() 是两类 CG。主问题在每船每泊位的所有可行进出时刻中定价。子问题按 EC.2 的双向标签和休息连接定价；前后紧邻休息的两个任务仍须满足式 (22) 的换岗时间。

网络节点是 (task, time)。休息节点按班次区分，源/汇使用同一个虚拟编号。休息时间在相同任务序列与位置下不影响成本和分支，所以只保存最早可行休息时间，去掉等价列。

## 约化成本和割符号

最小化 LP 的约化成本为 c - Σ(rowDual × columnCoefficient)。BMP 的最优性割行是：

η - Σω(δin + δout)χω >= 0。

因此船舶列在该行的系数是负的，定价时贡献是 +cutDual × (δin + δout)。约束 (39)–(41) 为 <=1，其 COPT 对偶通常非正；占用资源使约化成本增加。

PBSP 覆盖等式的对偶为 δ，引航员列约化成本为 pilotCost - Σvisited δ。每列至少包含一个任务时刻，且每个时刻的需求不超过 1；非负覆盖等式推得该列的 μ 不超过 1。因此上界 (47) 冗余，去掉它可取 ζ=0，式 (54) 不需要上界对偶常数。船舶列的 χ<=1 同样由单船 assignment 等式推得。

不能在一个仅由正需求节点构成的限制网络上停止后就随意把其他 δ 设为零生成割。本实现保留全部合法时刻的覆盖行，正常 CG 优先使用正需求网络，收敛前在全部合法节点上再定价。这样返回的 δ 满足所有当前节点可用路线的对偶约束。

## 不可行分支和数值处理

未分支时的 PBSP 有足够多的引航员可用。邻接分支却可能使特定主问题方案无法安排引航员。对此，Phase I 在等式中加入正负松弛，最小化总违反量。完整定价后若目标仍为正，其对偶给出必要条件 Σω αωδ χω <= 0，作为可行性割加入 BMP。若 BMP 的 Phase I 也不能把人工变量归零，则节点不可行。

优化结果必须为 LP OPTIMAL，才能读取用于定价的对偶。PBSP 会检查原对偶目标一致。CG 中途的 RMP 值不会当作完整问题下界；超时仍保留父节点已认证下界。

休息连接取 max(previousEnd + setupToRest, restEarliest)，再检查休息最晚开始与后任务开始。这避免了 EC.3 所印 min 表达式可能让休息早于前任务结束的问题，与正文的可行性要求及作者公开实现的连接规则相符。

## 分支与搜索

按照 (60)–(63) 的顺序选择最接近 0.5 的分数聚合量：泊位、任务时刻、任务班次、活动邻接。0 分支禁止对应选择，1 分支禁止与其冲突的其他选择。休息和源/汇可被多条引航员路线共用，不能像物理任务那样强制只有一个入/出邻接。

每个节点重新构建主子问题，割和列只在节点内复用；没有实现论文的跨节点 WS。搜索采用 best-bound，找到整数可行方案后用其真实成本更新上界。输出整数方案前检查船舶 assignment、泊位/航道资源、分支限制和任务覆盖耦合。

静态资源行中，若某个 headway/non-simultaneity 行最多可能含一个物理任务，它已被该任务的单位 assignment 隐含。本实现只省略这些冗余行，其他可能冲突的行一开始就加入；这与论文 DCG 的动态分离有区别。

## 验证覆盖

Verify.java 独立枚举时间有序任务序列，再显式枚举每一个休息位置和时间；不调用标签算法来判断最短路径是否正确。

完整 M2 LP 使用全部枚举船舶/引航员列，并重新构造全部泊位、headway、非同时性及任务耦合行。整数 oracle 则枚举船舶方案，并通过任务子集动态规划计算精确引航员排班成本。LP 与整数 oracle 是两个不同计算过程。

当前验证包含所有四类分支、父节点禁止的邻接不能被子节点恢复、分支后不可行、航道冲突、全网络对偶不等式及超时不伪造解。公开实例仅跑通了一个；更大规模与其他数据尚未完成实验。
